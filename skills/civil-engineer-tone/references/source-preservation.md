# 윤문 전후 원문 대조

수치가 있는 문서를 윤문하거나 유사 사업 성과품을 참고할 때 읽는다. 문체 등급은 기술 검토·사실 확인 결과가 아니다.

## 바꾸면 안 되는 의미

| 원문 구분 | 유지할 내용 | 잘못된 윤문 예 |
|---|---|---|
| 계획 / 완료 | 예정·협의 중·일부 반영·반영 완료의 상태 | `반영 예정` → `반영하였음` |
| 의무 / 허용 | 하여야 한다·할 수 있다·권장한다의 강도 | `설치할 수 있다` → `설치하여야 한다` |
| 부정 / 조건 | 제외·미실시·미확정·이상/이하·조건부 적용 | `검토하지 않음` → `검토하였음` |
| 당초 / 변경 | 각 값이 어느 열·시설·대안에 속하는지 | 당초와 변경의 수치는 그대로지만 열 위치를 뒤바꿈 |
| 기준 / 판정 | 적용 기준, 검토값, O.K/N.G, 판단의 근거 | 문장을 매끈하게 하면서 미달을 만족으로 바꿈 |

문체 규칙보다 원문 의미가 우선이다. 누락된 승인 여부·근거·계산값을 유사 사업에서 가져와 채우지 않는다. 사실관계가 모순되면 문체 수정과 분리해 `[확인 필요]`로 남긴다.

## 수치 대조 스크립트

```bash
python scripts/check_values.py 원문.md 윤문.md
python scripts/check_values.py 원문.md 윤문.md --json
```

- 입력은 UTF-8 텍스트·Markdown이며 BOM도 허용한다. HWP·PDF·Excel은 텍스트 추출 결과를 넣고, 표 구조 손실 여부는 원문에서 확인한다.
- 원문과 윤문 파일을 수정하지 않는다. 종료 코드는 `0` 차이 미검출, `1` 대조 필요, `2` 입력 오류다.
- 어휘집의 자동 표기 정규화 후 숫자·인식한 단위·부등호의 **출현 개수**를 비교한다. 예: `1,200 m3/day`와 `1200㎥/일`, `13km`와 `13.0km`는 같다.
- 숫자 변경·누락·추가, 같은 숫자의 반복 개수, `MPa`→`kPa`, 음수→양수, `≤`→`≥`의 차이를 표시한다. 원문·윤문 양쪽의 후보 행과 문맥은 JSON에 포함된다. 반복된 값의 어느 행이 누락됐는지는 자동 확정하지 않는다.
- `1km`→`1000m` 같은 **단위 환산은 검토 대상으로 남긴다**. 날짜·문서 번호도 숫자로 비교하므로 목차 재번호 등 의도한 변경은 따로 확인한다.
- Markdown fenced code는 본문에서 제외한다. 코드 안의 값이 실제 설계 근거라면 별도로 대조한다.

이 도구는 일부 수치 변경을 빨리 찾는 보조 검사다. 같은 값이 다른 시설에 붙은 경우, 표 머리글 단위, 미지원 단위, 숫자가 없는 사업명·기관명·근거, 조건·부정·완료 상태는 자동 검증하지 못한다. **차이 미검출을 '원문 사실 보존 완료'라고 보고하지 않는다.**

## 공유자료를 근거로 사용할 때

자료지도·파일명·미리보기는 원문 위치를 찾는 단서다. 본문을 실제로 열기 전에는 용어·문체 규칙의 근거로 확정하지 않는다. 특히 `최종`이라는 이름만으로 승인본·최신본으로 판단하지 않는다.

로컬 근거 대장에는 다음을 남긴다. 공개 저장소에는 실제 공유 주소·직원명·사업명·원문·실제 수치를 싣지 않고 가상 예시만 사용한다.

| 항목 | 기록 예시(가상) |
|---|---|
| 자료 식별 | 로컬 자료ID 및 원본 위치 |
| 확인 위치 | 본문 제○장 제○절, ○쪽, 표 ○-○ |
| 분야·유형 | 교통 / 보고서 R / 기본설계 |
| 확인 수준 | 파일명만 / 미리보기만 / 본문 일부 / 여러 독립 사업 대조 |
| 관찰 규칙 | 조건부 판단 종결을 쓰는 문맥과 예외 |
| 검토 상태 | 후보 / 재현 확인 / 분야 검토 완료 |

같은 사업의 복사본을 독립 근거 여러 건으로 세지 않는다. 수집 경로 수, 본문 확인 문서 수, 회귀시험 통과 수는 서로 다른 지표로 기록한다.
